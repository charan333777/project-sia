# Sia REST API V1

Base path: `/api/v1`

Success responses use `{ "data": ... }`. Errors use `{ "error": { "code": "...", "message": "..." } }`. Protected requests require `Authorization: Bearer <supabase-access-token>`.

## `GET /health`

Public. Returns `200` with `{ "data": { "status": "ok" } }`.

## `POST /profiles`

Protected. Creates the authenticated user's only V1 profile and returns `201`.

```json
{
  "username": "zach",
  "display_name": "Zach",
  "role": "AI Engineer",
  "bio": "Learning about AI and building useful things.",
  "current_context": "Heading to an AI meetup",
  "interests": ["AI", "Startups"],
  "open_to": ["A quick chat", "Coffee"],
  "is_public": true,
  "profile_theme": "calm",
  "profile_character": "elephant"
}
```

Possible errors include `400 VALIDATION_ERROR`, `401 UNAUTHORIZED`, `409 USERNAME_TAKEN`, and `409 PROFILE_EXISTS`.

## `GET /profiles/me`

Protected. Returns the verified user's profile or `404 PROFILE_NOT_FOUND`.

## `PATCH /profiles/me`

Protected. Accepts any subset of the create-profile fields. The service merges the patch with the stored profile, validates the complete result, and updates only the verified owner's row.

## `GET /public/profiles/:username`

Public. Normalizes the username and returns a public profile. A missing or non-public profile returns the same `404 PROFILE_NOT_FOUND` response to avoid disclosing private records.

## Validation limits

- Username: 3–30 lowercase letters, numbers, `_` or `-`; cannot begin/end with punctuation; system route names are reserved.
- Display name: 1–60 characters.
- Role: up to 80 characters.
- Bio: up to 300 characters.
- Current context: up to 160 characters.
- Interests and open-to values: up to 10 unique values, 40 characters each.
- Profile theme: `calm`, `warm`, `bold`, or `play`.
- Profile character: `plain`, `puppy`, `elephant`, `panda`, or `play`.
