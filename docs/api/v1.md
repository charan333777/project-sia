# Sia REST API V1

Base path: `/api/v1`

Success responses use `{ "data": ... }`. Errors use `{ "error": { "code": "...", "message": "..." } }`. Protected requests require `Authorization: Bearer <supabase-access-token>`.

## `GET /health`

Public. Returns `200` with `{ "data": { "status": "ok" } }`.

## `POST /profiles`

Protected. Creates the authenticated user's only V1 profile and returns `201`.

```json
{
  "username": "zach",
  "display_name": "Zach",
  "role": "AI Engineer",
  "bio": "Learning about AI and building useful things.",
  "current_context": "Heading to an AI meetup",
  "interests": ["AI", "Startups"],
  "open_to": ["A quick chat", "Coffee"],
  "is_public": true,
  "profile_theme": "calm",
  "profile_character": "elephant"
}
```

Possible errors include `400 VALIDATION_ERROR`, `401 UNAUTHORIZED`, `409 USERNAME_TAKEN`, and `409 PROFILE_EXISTS`.

## `GET /profiles/me`

Protected. Returns the verified user's profile or `404 PROFILE_NOT_FOUND`.

## `PATCH /profiles/me`

Protected. Accepts any subset of the create-profile fields. The service merges the patch with the stored profile, validates the complete result, and updates only the verified owner's row.

## `POST /profiles/me/photo`

Protected. Accepts one `multipart/form-data` field named `photo`. JPEG, PNG, and WebP files up to 5 MB are accepted after file-signature validation and metadata stripping. Uploading a new photo replaces the previous object and returns the updated profile with a short-lived `avatar_url`.

## `DELETE /profiles/me/photo`

Protected. Removes the authenticated user's photo and returns the updated profile. The profile falls back to its selected Sia character or initial.

## `GET /public/profiles/:username`

Public. Normalizes the username and returns a public profile. A missing or non-public profile returns the same `404 PROFILE_NOT_FOUND` response to avoid disclosing private records.

## Nearby endpoints

All Nearby endpoints are protected, return `Cache-Control: no-store`, and are scoped to the verified user.

- `GET /nearby`: returns current presence, approximate nearby profiles, pending Waves, temporary connections, and Meet Cards.
- `PUT /nearby/presence`: opts in or refreshes presence with `latitude`, `longitude`, `accuracy_m`, and a duration of `15m`, `60m`, or `until_leave`.
- `DELETE /nearby/presence`: hides immediately and deletes the user's stored location.
- `POST /nearby/signals`: sends one preset intention to a profile currently within 200 m.
- `PATCH /nearby/signals/:id`: accepts or declines an incoming Wave. Acceptance creates a two-hour mutual connection.
- `POST /nearby/connections/:id/meet-plans`: suggests a time within two hours and a short public-place label.
- `PATCH /nearby/meet-plans/:id`: accepts, declines, or cancels a meeting proposal.
- `POST /nearby/meet-plans/:id/statuses`: sends a preset coordination update such as `coming`, `here`, or `five_minutes` after acceptance.
- `POST /nearby/blocks/:profileId`: blocks the profile and closes pending/active interactions.
- `POST /nearby/reports`: creates a moderation report without exposing it to other users.

The API never returns latitude, longitude, raw distance, or exact bearing. Nearby uses no free-form chat; only validated intentions, meeting labels, and preset statuses are accepted.

## Validation limits

- Username: 3–30 lowercase letters, numbers, `_` or `-`; cannot begin/end with punctuation; system route names are reserved.
- Display name: 1–60 characters.
- Role: up to 80 characters.
- Bio: up to 300 characters.
- Current context: up to 160 characters.
- Interests and open-to values: up to 10 unique values, 40 characters each.
- Profile theme: `calm`, `warm`, `bold`, or `play`.
- Profile character: `plain`, `puppy`, `elephant`, `panda`, or `play`.
- Profile photo: optional JPEG, PNG, or WebP; up to 5 MB after browser-side square cropping and resizing.
